# 各环节提示词模板

从真实项目提炼的高效提示词模板。`{占位符}` 替换为实际内容。

## 1. 需求分析提示词（九段式）

适用：新功能立项。产出的文档本身就是后续实现环节的输入。

```markdown
# {功能名称} — 需求提示词

## 项目背景
基于现有 {项目名}（{目录}），需要实现 {功能一句话描述}。

## 一、业务规则
{用表格列出对象分类及处理方式差异}

### 状态流转
{用文本图画出状态机，标明每个转换的触发者}
示例：
积分兑换实物 → pending（待发放）
                ↓ 管理员操作
            fulfilled（已兑现）或 rejected（已拒绝，退还积分）

## 二、数据模型
文件：backend/app/models.py
{给出目标表结构的 SQLAlchemy 代码，新增字段标注可空性与用途注释}

## 三、后端 API
文件：backend/app/routers/{xxx}.py
{每个接口给出：方法+路径+鉴权头+请求体+响应示例 JSON}

## 四、业务逻辑
文件：backend/app/services/{xxx}_service.py
{用带注释的伪代码描述核心规则与分支}

## 五、前端实现
{列出涉及的 HTML 区块、JS 数据与方法名、CSS 要点}

## 六、移动端适配要求
{表格：元素 | 桌面端表现 | 移动端（≤640px）表现}

## 七、安全性要求
1. JWT 鉴权：所有管理接口需 Authorization: Bearer <token>
2. 角色校验：require_role("admin")，非管理员返回 403
3. 防重复操作：非法状态转换返回 400
4. 操作审计：记录 operated_by / operated_at / note
{补充功能特有安全项}

## 八、验收标准
- [ ] {可独立验证的验收项，一行一条}

## 九、文件清单
| 文件 | 状态 | 说明 |
|------|------|------|
{预先列出全部要动的文件}
```

## 2. 数据库迁移提示词

```
为 {表名} 新增 {字段列表} 字段，要求：
1. 编写 Alembic 迁移脚本 backend/alembic/versions/{下一序号}_{描述}.py
2. 防御式迁移：用 sqlalchemy.inspect 检查表存在、列不存在后再 add_column
3. 新列必须可空（nullable=True），存量行不回填则业务代码做 NULL 回退到默认值 {默认值}
4. 同步更新 models.py、schemas.py（出参可选字段）
5. 严禁重置数据库，严禁 drop/recreate 表
6. 本地先验证三场景：全新库、已有数据旧版本库、已是最新版本库（幂等）
```

## 3. 安全加固审计提示词

```
对 {项目目录} 做端到端安全审计并加固，逐项检查：
1. 密钥管理：SECRET 是否强制环境变量注入？是否拒绝弱密钥（<32字符/低熵/常见弱词）？
2. 密码策略：是否加盐哈希？最小长度≥8？用户名是否限制字符集？
3. Token：有效期是否≤7天？重启后是否失效（.secret_key 落盘复用）？
4. CORS：白名单是否收窄到实际来源？方法/请求头是否收窄？
5. 安全响应头：X-Frame-Options / X-Content-Type-Options / X-XSS-Protection
6. 速率限制：登录/改密/上传等敏感接口
7. 上传安全：魔数校验、SVG/HTML 伪装检测、尺寸上限
8. 敏感数据：生物特征/身份证等是否加密存储？
9. 容器：是否非 root 运行？
10. Git：*.db/.secret_key/.env/uploads/ 是否已忽略？历史提交中是否有泄漏？
每项输出：现状 → 风险等级 → 修复方案 → 修复后验证方式。修复不得破坏现有功能，完成后跑全量回归测试。
```

## 4. 部署提示词

```
将最新代码部署到以下环境，使用 scripts/deploy.sh，记录日志与所有问题：
1. 本地测试环境（Docker）：重建镜像更新容器；保留数据卷（数据库+上传文件）；验证服务启动与功能
2. 生产服务器 {IP}：SSH 远程部署；更新前自动备份数据库（WAL 感知）；
   完整代码更新与镜像重建；数据持久化卷不删除；验证服务与功能；
   部署后功能测试确认 {本次新功能} 在生产正常
要求：部署前先只读预检（现有容器配置/数据目录/迁移版本基线）；部署后行数逐项对比确认零数据丢失。
```

## 5. 回归测试提示词

```
为 {项目} 建立回归测试体系：
1. tests/ 目录按模块拆分：test_auth.py、test_{业务模块}.py…
2. 公共工具 test_utils.py：起测试服务、注册/登录取 token、断言助手
3. run_all.py 一键全量执行，输出通过/失败统计
4. 每个功能覆盖四类用例：正常路径、权限拒绝(403)、非法状态/重复操作(400)、边界值
5. 测试用独立数据库，不污染开发数据
```

## 6. Bug 修复提示词

```
问题现象：{具体表现，含复现步骤和报错原文}
排查要求：
1. 先复现并定位根因，给出证据链（日志/请求/数据状态），不允许猜测性修改
2. 说明影响范围：哪些接口/页面/数据受影响
3. 最小化修复，不顺手重构
4. 修复后：原场景复现验证 + 相关模块回归测试
5. 若属通用陷阱（如时区/路径/缓存），沉淀为项目经验记录
```

## 7. 前端页面提示词

```
为 {管理后台|用户端} 新增 {页面/区块}：
1. 技术：Vue3 CDN 模式（现有 app.js 内追加 data/methods），不引入构建工具
2. 资源引用一律相对路径 ./xxx，适配子路径部署
3. 桌面端 {布局}；移动端 ≤640px {卡片/底部Tab}，按钮≥44px、输入字号≥16px
4. 所有请求走统一 API base（运行时探测子路径前缀）
5. 完成后更新资源版本号 ?v={日期}，并在浏览器验证桌面+移动两种视口
```
