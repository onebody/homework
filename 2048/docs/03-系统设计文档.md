### 架构设计

整体采用纯前端三层架构，无后端服务：

```
┌─────────────────────────────────────────┐
│              表现层 (View)               │
│    index.html + style.css               │
│    负责DOM渲染、动画、触屏事件捕获        │
├─────────────────────────────────────────┤
│              逻辑层 (Logic)              │
│    game.js - Game2048 类                │
│    棋盘数据、移动合并算法、分数计算       │
│    游戏状态判定、LocalStorage存档        │
├─────────────────────────────────────────┤
│              数据层 (Storage)            │
│    LocalStorage                         │
│    key: game2048_state                  │
│    存储棋盘JSON、分数、最高分            │
└─────────────────────────────────────────┘
```

逻辑层与表现层分离：`Game2048`类是纯逻辑模块，不依赖DOM，可独立进行单元测试。表现层通过调用`Game2048`实例的方法获取状态，然后渲染DOM。

## 模块设计

### Game2048 核心类

`Game2048`类封装全部游戏逻辑，对外暴露以下方法：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `constructor(size)` | size: 棋盘尺寸，默认4 | 实例 | 初始化空棋盘 |
| `init()` | 无 | void | 重置棋盘，生成两个初始方块 |
| `move(direction)` | direction: 'up'\|'down'\|'left'\|'right' | `{moved: boolean, score: number}` | 执行移动，返回是否发生移动和本次得分 |
| `getBoard()` | 无 | `number[][]` | 获取当前棋盘数据副本 |
| `getScore()` | 无 | `number` | 获取当前分数 |
| `isGameOver()` | 无 | `boolean` | 判断游戏是否结束 |
| `hasWon()` | 无 | `boolean` | 判断是否已合成2048 |
| `canMove()` | 无 | `boolean` | 判断是否还能移动 |
| `serialize()` | 无 | `object` | 序列化为可存储对象 |
| `static deserialize(data)` | data: object | `Game2048` | 从存档恢复实例 |

### 移动合并算法

移动是游戏最核心的算法，四个方向的逻辑相同，通过"旋转棋盘"统一处理：

1. 将棋盘旋转/翻转，使目标方向始终变为"向左"
2. 对每一行执行左移操作：
   - 过滤掉零值（去除空格）
   - 从左到右遍历，相邻相同值合并（合并后标记已合并，防止连锁合并）
   - 在末尾补零至原长度
3. 将棋盘旋转回原始方向
4. 比较移动前后棋盘，判断是否发生变化
5. 若有变化，在随机空格生成新方块

左移处理示例：
```
输入行: [2, 0, 2, 4]
过滤零: [2, 2, 4]
合并:   [4, 4]    （第一个2和第二个2合并，得4分）
补零:   [4, 4, 0, 0]
```

### 随机方块生成

每次有效移动后，从所有值为0的单元格中随机选取一个，以90%概率填入2、10%概率填入4。使用`Math.random()`生成随机索引。

### 游戏结束判定

满足以下两个条件时游戏结束：
1. 棋盘中不存在值为0的单元格（棋盘已满）
2. 不存在任何相邻（水平或垂直）的相同数值方块

### 动画设计

| 动画 | 触发时机 | CSS属性 | 时长 | 缓动函数 |
|------|---------|---------|------|---------|
| 新方块出现 | 方块生成 | transform: scale(0→1) | 150ms | ease-out |
| 方块合并 | 两个方块合并 | transform: scale(1→1.1→1) | 200ms | ease-in-out |
| 分数增加 | 合并得分 | transform: scale(1→1.2→1) | 200ms | ease-out |
| 方块移动 | 滑动操作 | transform: translate | 100ms | ease-in-out |

### 遮罩层设计

游戏胜利或结束时，棋盘上方覆盖半透明遮罩层：

- 胜利遮罩：背景色 `rgba(237, 194, 46, 0.5)`，显示"你赢了！"文字，提供"继续游戏"和"新游戏"按钮
- 失败遮罩：背景色 `rgba(238, 228, 218, 0.73)`，显示"游戏结束！"文字，提供"再来一局"按钮

## 触屏交互设计

### 事件处理流程

```
touchstart ──▶ 记录起始坐标 (startX, startY)
     │
touchmove  ──▶ preventDefault() 阻止页面滚动
     │
touchend   ──▶ 计算偏移量 (deltaX, deltaY)
               │
               ├─ abs(deltaX) > abs(deltaY) ?
               │     ├─ deltaX > 30 → move('right')
               │     └─ deltaX < -30 → move('left')
               │
               └─ 否则
                     ├─ deltaY > 30 → move('down')
                     └─ deltaY < -30 → move('right')
```

事件监听绑定在棋盘容器元素上，而非document，避免干扰页面其他区域的正常滚动。

## 响应式方案

使用CSS自定义属性和媒体查询实现适配：

```css
:root {
  --board-size: min(calc(100vw - 32px), 480px);
  --cell-size: calc((var(--board-size) - 40px) / 4);
  --cell-gap: 10px;
}
```

棋盘尺寸使用`min()`函数在视口宽度和最大宽度间取较小值，单元格尺寸由棋盘尺寸减去间距后均分。所有尺寸使用px（通过CSS计算），无需JS动态计算，性能更好。

## 渲染策略

采用全量重渲染策略：每次移动后，根据棋盘数据重新生成所有方块的DOM。这种方式实现简单，对于4x4=16个单元格的场景性能足够。为实现动画效果，使用以下策略：

1. 移动前记录每个方块的位置
2. 更新数据后，将新位置的方块transform到旧位置
3. 在下一帧（requestAnimationFrame）移除transform，触发CSS transition产生位移动画
4. 新方块添加`.new`类触发出场动画
5. 合并方块添加`.merged`类触发脉冲动画

考虑到实现复杂度和性能平衡，实际编码中可采用简化方案：每次移动后全量渲染DOM，新方块通过CSS animation自动播放入场动画。位移动画在后续优化中加入。
