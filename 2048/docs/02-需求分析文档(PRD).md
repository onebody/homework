## 需求背景

2048是一款由Gabriele Cirulli于2014年发布的数字合并益智游戏，玩法简单但策略深度充足，上线后迅速风靡全球。移动端浏览器天然适合这类轻量级休闲游戏：无需下载安装、即开即玩、单局时间短（3-10分钟），适合通勤、排队等碎片化场景。

当前市场上的2048 H5版本普遍存在三个问题：触屏滑动不跟手、页面尺寸不适配小屏手机、缺少游戏进度保存导致刷新即丢失。本项目旨在用纯原生H5技术实现一款体验流畅的手机版2048，解决上述痛点。

## 需求目标

开发一款在手机浏览器中即开即玩的2048游戏，核心体验指标如下：

- 触屏滑动响应延迟低于100ms，滑动方向判定准确
- 在320px至480px宽度的手机屏幕上完整显示游戏区域，无需横向滚动
- 游戏状态（棋盘数据、当前分数）自动保存，刷新页面或关闭浏览器后可恢复
- 首屏加载时间低于2秒（4G网络），文件总体积小于100KB

## 目标用户

| 用户画像 | 描述 |
|---------|------|
| 通勤族 | 25-40岁，上下班途中用手机浏览器消磨时间，单局游戏5分钟左右 |
| 休闲游戏玩家 | 18-35岁，喜欢益智类游戏，追求高分挑战 |
| 微信内置浏览器用户 | 通过社交分享链接进入游戏，期望即点即玩，无需跳转下载 |

## 功能需求详述

### 模块一：游戏棋盘

游戏棋盘是核心交互区域，为一个4x4的网格，占据屏幕中央主要位置。

**页面布局：**

棋盘区域由16个单元格组成，以4行4列排列。每个单元格具有圆角和浅色背景，方块出现时覆盖在单元格上方。棋盘四周留有适当内边距，整体宽度根据屏幕宽度自适应，最大不超过屏幕宽度减去两侧32px边距。棋盘上方显示标题"2048"和分数面板，下方显示操作提示和重新开始按钮。

**业务逻辑：**

游戏初始化时，棋盘中随机生成两个初始方块，数值为2（90%概率）或4（10%概率）。玩家通过滑动手势控制所有方块朝滑动方向移动。方块移动时遵循以下规则：同一方向上，每个方块会一直滑动直到碰到棋盘边界或另一个方块；如果两个相同数字的方块在移动中碰撞，它们合并为一个方块，数值为两者之和，合并后的方块在本次移动中不能再次合并。每次有效移动后（即至少有一个方块发生了位置变化或合并），在空白单元格中随机生成一个新方块（90%概率为2，10%概率为4）。

**字段规则：**

| 字段 | 类型 | 范围 | 说明 |
|------|------|------|------|
| 棋盘数据 | 二维数组 | 4x4，元素为0或2的幂 | 0表示空格，非零值表示方块数值 |
| 方块位置 | 行列坐标 | 行0-3，列0-3 | 方块在棋盘中的位置 |
| 方块数值 | 整数 | 2, 4, 8, 16, ... 2048+ | 只能是2的幂次方 |

**边界与异常：**

当棋盘已满且不存在任何可合并的相邻方块时，游戏结束。当任意方块数值达到2048时，判定为游戏胜利，显示胜利提示，但玩家可以选择继续游戏挑战更高分数。

### 模块二：分数系统

分数面板位于棋盘上方右侧，实时显示当前分数和历史最高分。

**业务逻辑：**

每次方块合并时，玩家获得与合并后数值相等的分数。例如两个2合并为4，得4分；两个512合并为1024，得1024分。当前分数在每次移动后实时更新。历史最高分通过LocalStorage持久化存储，当当前分数超过历史最高分时，最高分自动更新。页面刷新后，当前分数和最高分均从LocalStorage恢复。

分数变化时，分数面板应有短暂的数值放大动效，给玩家即时反馈。新生成的方块和合并产生的方块也应有出现/放大动画。

**字段规则：**

| 字段 | 类型 | 范围 | 存储位置 |
|------|------|------|---------|
| 当前分数 | 整数 | 0 - 无限 | 内存 + LocalStorage |
| 最高分 | 整数 | 0 - 无限 | LocalStorage |

### 模块三：触屏操作

触屏滑动是移动端的核心操作方式，玩家在棋盘区域用手指向上下左右任一方向滑动，控制方块移动。

**交互逻辑：**

玩家手指在棋盘区域按下时记录起始坐标，手指移动时不触发操作，手指抬起时计算滑动距离和方向。水平滑动距离大于竖直滑动距离且超过30px阈值时判定为水平方向滑动，反之判定为竖直方向滑动。滑动方向判定后执行对应方向的方块移动逻辑。如果滑动距离不足30px，视为误触，不执行任何操作。在棋盘区域内的touchmove事件需阻止默认行为，防止页面滚动干扰游戏操作。

同时支持键盘方向键（上、下、左、右）操作，方便在PC端调试和体验。键盘操作与触屏操作共用同一套移动逻辑。

### 模块四：游戏状态管理

游戏状态包括棋盘数据、当前分数、游戏是否结束、是否已胜利。

**业务逻辑：**

每次有效移动后，将棋盘数据（4x4二维数组序列化为JSON）和当前分数保存到LocalStorage。页面加载时，检查LocalStorage中是否存在存档，若存在则恢复棋盘和分数，若无存档则初始化新游戏。游戏胜利（合成2048）后显示胜利遮罩层，提供"继续游戏"和"新游戏"两个按钮。游戏结束（无法移动）后显示失败遮罩层，提供"再来一局"按钮。

新游戏按钮点击后，清空LocalStorage存档，重置分数为0，重新生成两个初始方块。

**状态转换：**

| 当前状态 | 触发条件 | 下一状态 |
|---------|---------|---------|
| 初始化 | 页面加载，无存档 | 进行中 |
| 进行中 | 合成2048方块 | 胜利（可继续） |
| 胜利（可继续） | 玩家点击"继续游戏" | 进行中 |
| 进行中 | 棋盘满且无可合并方块 | 游戏结束 |
| 任意状态 | 玩家点击"新游戏" | 初始化 |

### 模块五：视觉与动画

游戏采用浅色主题，不同数值的方块使用不同背景色，数值越大颜色越深，形成视觉层次。

**视觉规范：**

方块颜色参考经典2048配色：2为浅米色、4为浅橙色、8为橙色、16为深橙色、32为橙红色、64为红色、128为浅黄色、256为黄色、512为金黄色、1024为深金色、2048为深金色带发光效果。超过2048的数值使用深色背景。文字颜色根据背景深浅自动切换（浅色背景用深灰文字，深色背景用白色文字）。

新方块出现时有从0放大到1的缩放动画（持续150ms）。方块合并时有短暂的脉冲放大动画（先放大到1.1倍再回到1倍，持续200ms）。方块移动时有位移动画（持续100ms），使用CSS3 transform实现以获得GPU加速。

### 模块六：响应式适配

游戏界面需适配不同尺寸的手机屏幕。

**适配规则：**

棋盘宽度根据视口宽度动态计算，公式为：`棋盘宽度 = min(视口宽度 - 32px, 480px)`。棋盘高度与宽度相等，保持正方形。单元格大小根据棋盘宽度减去间距后平均分配。根元素font-size根据视口宽度动态设置，所有尺寸使用rem单位，实现整体等比缩放。在横屏模式下，棋盘尺寸取视口高度和宽度中的较小值作为基准，确保棋盘完整可见。

## 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 方块移动动画帧率不低于60fps；首屏加载不超过2秒 |
| 兼容性 | 支持iOS Safari 14+、Chrome Mobile 90+、微信内置浏览器、QQ浏览器 |
| 体积 | 单个HTML文件 + 一个CSS文件 + 一个JS文件，总体积小于100KB（未压缩） |
| 可访问性 | 方块文字与背景对比度不低于4.5:1；支持键盘操作 |
| 离线能力 | 首次加载后可离线游玩（通过LocalStorage存档，无需Service Worker） |
